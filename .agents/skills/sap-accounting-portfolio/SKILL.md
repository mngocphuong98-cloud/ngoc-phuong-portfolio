# SAP Accounting Portfolio Skill

Use this skill whenever adding or editing SAP Knowledge Base content or accounting case studies.

## Purpose

The site must demonstrate:
- business understanding
- SAP process understanding
- reconciliation thinking
- root-cause analysis
- repeatable controls
- ability to convert work experience into reusable knowledge

Do not reduce expertise to a list of T-codes.

## Knowledge article structure

Use this sequence when enough information is available:

1. Business Situation
2. Why It Matters
3. SAP Logic
4. Relevant Transactions / Reports
5. Preconditions
6. Step-by-Step Check
7. Reconciliation
8. Common Errors
9. Root-Cause Questions
10. What I Learned
11. Related Topics

For short notes, use:
- When to use
- What to check
- Relevant T-codes
- Watch-outs

## Case study structure

Each case study should show:

### Problem
What operational or accounting problem existed?

### Evidence / Data
Which reports, transactions, spreadsheets or source documents were used?

### Reasoning
How was the issue narrowed down?

### Solution
What was changed, corrected or automated?

### Control
How can the issue be detected earlier next time?

### Value
What became clearer, faster, safer or more repeatable?

Avoid fake ROI or invented percentages.

## T-code rule

A T-code should never stand alone.

Instead of:
`KKA0 · KSII · CKMLCP · CO88H`

Explain the process:
`Activity allocation → WIP → Material Ledger → Settlement → GL reconciliation`

Then show the relevant T-codes as supporting technical detail.

## Troubleshooting framework

For SAP errors, investigate in this order:

1. Period
2. Master data / configuration
3. Transaction data
4. Status / organizational assignment
5. Process sequence
6. Accounting impact

An SAP error message is a symptom location, not automatically the root cause.

## Confidentiality

Public content must generalize or remove:
- company names
- customer/vendor identities
- internal PO/SO/order numbers
- sensitive account details
- actual monetary values
- screenshots with live business data

Synthetic examples are preferred for demonstration.

## Language

Vietnamese:
- explain business logic naturally
- keep standard SAP terms in English when commonly used

English:
- use clear professional accounting language
- avoid literal word-for-word translation
- preserve SAP terminology accurately

## Editorial standard

Write in a way that a hiring manager can understand even if they do not know every SAP transaction.

The page should make the reader think:
"This person understands why the control exists and how to investigate when it fails."
